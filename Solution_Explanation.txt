=====================================================================
   ORDER MANAGEMENT SYSTEM (JDBC + MySQL) - SOLUTION FOR EACH PART
=====================================================================

Database : ecommerce_db
Table    : Orders
    order_id      INT PRIMARY KEY
    customer_name VARCHAR(100)
    product_name  VARCHAR(100)
    quantity      INT
    unit_price    DOUBLE
    status        VARCHAR(30)

Code (src/main/java/com/example/ordermanagement):
    console/OrderManagementConsole.java -> menu-driven program
    controller/OrderController.java     -> REST API (Postman)
    model/Order.java                    -> Model
    dao/DBConnection.java               -> connection
    dao/OrderDao.java                   -> all SQL (PreparedStatement)
    service/OrderService.java           -> rules of parts (a)-(e)

REST endpoints (base http://localhost:8080/api/orders):
    (a) POST   /bulk            (a) POST   /       (single)
    (b) GET    /status/{status}
    (c) PUT    /{id}/quantity   body {"additionalQuantity": 4}
    (d) PUT    /{id}/status     body {"status": "Shipped"}
    (e) GET    /total-value     (e) DELETE /{id}

---------------------------------------------------------------------
(a) Connection + insert at least 3 orders, handle duplicate IDs
    OrderDao.insert() + OrderService.addOrder()
---------------------------------------------------------------------
Connection:
    Connection con = DriverManager.getConnection(
        "jdbc:mysql://localhost:3306/ecommerce_db?createDatabaseIfNotExist=true",
        "root", "root");          (in DBConnection.getConnection())
SQL:
    INSERT INTO Orders (order_id, customer_name, product_name,
                        quantity, unit_price, status)
    VALUES (?, ?, ?, ?, ?, ?)
Explanation:
  - The user says how many orders to insert; less than 3 is refused.
  - ps.setInt / setString / setDouble fill the ? placeholders and
    ps.executeUpdate() inserts each row.
  - Duplicate order ID: checked first with
        SELECT COUNT(*) FROM Orders WHERE order_id = ?
    and SQLIntegrityConstraintViolationException (primary key error)
    is also caught. Either way: "Order ID already exists. Record
    skipped." and the program continues.
  - Status must be Pending / Shipped / Delivered / Cancelled.
    Quantity must be > 0 and price cannot be negative.

---------------------------------------------------------------------
(b) Orders with a given status and quantity > 2, unit price DESC
    OrderDao.findByStatusWithQuantityAbove2()
---------------------------------------------------------------------
SQL:
    SELECT * FROM Orders
    WHERE status = ? AND quantity > 2
    ORDER BY unit_price DESC
Explanation:
  - ps.setString(1, status); executeQuery() returns a ResultSet.
  - while (rs.next()) prints each row; ORDER BY ... DESC puts the
    highest unit price first. If nothing matches, a message is shown.

---------------------------------------------------------------------
(c) Increase quantity of an order
    OrderDao.addQuantity()
---------------------------------------------------------------------
SQL:
    UPDATE Orders SET quantity = quantity + ? WHERE order_id = ?
Explanation:
  - executeUpdate() returns the number of rows changed.
    0 rows  -> "Order with ID x does not exist."
    1 row   -> success, and the updated order is printed.
  - Additional quantity must be greater than 0.

---------------------------------------------------------------------
(d) Retrieve order and update status (only if order exists and
    status is valid)   OrderService.updateStatus()
---------------------------------------------------------------------
SQL:
    SELECT * FROM Orders WHERE order_id = ?          (retrieve)
    UPDATE Orders SET status = ? WHERE order_id = ?  (update)
Explanation:
  - First the order is retrieved and displayed. If not found ->
    message, nothing updated.
  - New status is checked against Pending, Shipped, Delivered,
    Cancelled (case-insensitive, saved in proper form, e.g.
    "shipped" -> "Shipped"). Invalid -> message, nothing updated.
  - After the update the order is retrieved again and the updated
    details are displayed.
  - Cancelled is allowed so an order can be cancelled and then
    deleted in part (e).

---------------------------------------------------------------------
(e) Total order value + delete only Cancelled orders
    OrderService.deleteCancelledOrder()
---------------------------------------------------------------------
SQL:
    SELECT SUM(quantity * unit_price) AS total_value FROM Orders
    SELECT status FROM Orders WHERE order_id = ?
    DELETE FROM Orders WHERE order_id = ? AND status = 'Cancelled'
Explanation:
  - SUM(quantity * unit_price) multiplies each row's quantity and
    price, then adds them all = total value of all orders.
  - Before deleting, the status is read:
      not found          -> "does not exist. Cannot delete."
      not Cancelled      -> "Cannot delete ... Only Cancelled orders
                             can be deleted."
      Cancelled          -> deleted.
  - status = 'Cancelled' is repeated in the DELETE for safety.

VIVA - QUICK QUESTIONS
---------------------------------------------------------------------
Q: What is JDBC?
A: Java Database Connectivity - Java API to connect to and run SQL
   on a database. Main classes: DriverManager, Connection,
   PreparedStatement, ResultSet, SQLException.

Q: Steps of JDBC?
A: 1 Load driver (automatic since JDBC 4 when the JAR is on the
   classpath)  2 Get Connection  3 Create PreparedStatement
   4 Execute (executeQuery / executeUpdate)  5 Process ResultSet
   6 Close resources (done by try-with-resources here).

Q: Why PreparedStatement and not Statement?
A: Precompiled (faster when repeated), values are passed with
   setXxx() so it prevents SQL injection, and no string joining.

Q: executeQuery vs executeUpdate?
A: executeQuery -> SELECT, returns ResultSet.
   executeUpdate -> INSERT/UPDATE/DELETE, returns rows affected (int).

Q: How did you handle duplicate order IDs?
A: order_id is the PRIMARY KEY. I check with SELECT COUNT(*) first,
   and also catch SQLIntegrityConstraintViolationException.

Q: How do you know an order does not exist in part (c)?
A: executeUpdate() returns 0 rows affected.

Q: What does try-with-resources do?
A: Automatically closes Connection, PreparedStatement and ResultSet
   (they implement AutoCloseable), even if an exception occurs.

Q: What is the JAR in lib for?
A: MySQL Connector/J = the JDBC driver. Without it:
   "No suitable driver found for jdbc:mysql://..."

Q: What does ORDER BY unit_price DESC do?
A: Sorts results from highest to lowest unit price.

Q: What does SUM(quantity * unit_price) return?
A: The total value of all orders (aggregate function, one value).
